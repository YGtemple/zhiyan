# 01. 信息获取架构

## 设计原则

1. 信息获取是训练路由，不是注册问卷。
2. 首屏只问会影响基线测试、评分权重、训练任务的问题。
3. 每个字段必须声明用途：影响评分、影响训练、影响反馈、影响基线测试、影响隐私，或仅记录。
4. 用户自述痛点只作为上下文，必须再用口述文本证据验证。
5. 当前能力边界要明确：TEDify 只分析口述转写文本。
6. 材料上传、隐私、反馈风格等问题采用渐进披露，在真正需要前再问。
7. 除非会影响第一轮基线测试，否则默认允许跳过。

## 流程

### 1. 首屏路由

收集：

- 训练场景
- 当前准备阶段
- 听众类型
- 使用时间
- 目标时长
- 可选痛点

作用：

- 决定基线测试题
- 决定初始评分权重
- 决定第一轮训练模板

### 2. 场景细化

后置收集：

- 希望听众做什么或相信什么
- 是否有 Q&A / 答辩 / 追问
- 使用语言
- 听众熟悉度

作用：

- 改善听众适配
- 调整说服路径
- 决定是否加入答辩训练

### 3. 材料路径

后置收集：

- 暂不上传
- 文字稿
- 大纲
- PPT
- 音频作为转写来源
- 视频作为转写来源

注意：

音频和视频只能作为转写来源或未来能力入口。当前不能声称分析真实音色、真实语速、停顿、情绪或肢体语言。

### 4. 隐私门

材料上传前必须问：

- 是否包含个人隐私
- 是否包含公司机密
- 是否包含客户/第三方内容
- 是否属于面试或考试内容

用户应始终可以选择：

- 不上传
- 粘贴脱敏版本
- 只做无材料基线测试

### 5. 基线测试路由

基线测试由这些字段决定：

- `training_goal`
- `readiness_stage`
- `audience_type`
- `time_horizon`
- `target_duration`
- `topic_brief`

示例：

- 面试 + 今天 + 1 分钟：做 60 秒岗位匹配型自我介绍。
- 工作汇报 + 领导同事 + 3 分钟：用 90 秒说明结论、证据和下一步建议。
- 没有主题 + 课堂展示：用 60 秒讲一个最近学到的概念。
- 闲聊训练 + 朋友：用 60 秒回应一个日常话题，并自然提出一个追问。

## 推荐首屏字段

| 字段 | 问题 | 是否必问 | 作用 |
|---|---|---:|---|
| `training_goal` | 你这次主要想练哪类表达？ | 是 | 决定场景评分、样例、训练模板 |
| `readiness_stage` | 你现在准备到哪一步了？ | 是 | 决定写作助教、表达教练或直接训练 |
| `audience_type` | 这次主要讲给谁听？ | 是 | 决定听众适配和说服方式 |
| `time_horizon` | 这次表达什么时候要用？ | 是 | 区分救急模式和长期训练 |
| `target_duration` | 这次大概需要讲多久？ | 是 | 决定压缩要求和练习长度 |
| `primary_pain_points` | 你最想先改善哪一项？最多选 2 个。 | 否 | 对齐用户动机和反馈优先级 |

## 后置字段

- 反馈风格
- 材料类型
- 材料使用意图
- 隐私敏感度
- 希望听众采取的行动
- 听众熟悉度
- 是否有 Q&A
- 语言环境
- 重要程度
- 一句话主题
